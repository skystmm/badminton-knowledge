# 动作分析报告模板

> 用途：用户上传照片、视频（先抽帧）或口述动作问题后，生成本报告。严格按结构输出；素材不足时先列出「还缺什么素材」再给初步判断。

## 素材角度要求（先向用户说清楚）

| 分析对象 | 必需角度 | 补充角度 |
|---------|---------|---------|
| 高远球/吊球/杀球发力链条 | **侧面**（能看到架拍、倒拍、挥拍轨迹、击球点） | 背面（看转体是否充分） |
| 握拍、架拍 | 正面或背面，**拍柄和拍面清晰** | 侧面看虎口位置 |
| 步伐 | 侧面看启动和回动 | 45 度看脚的最后一步 |
| 双打站位/跑位 | 俯视或斜上方 | — |

### 视频素材拍摄要求（先向用户说清楚）

- **机位**：分析高远球/吊球/杀球必须侧面拍摄，距动作 3-5 米，全身入镜（从头到脚）；
- **帧率**：手机慢动作（120fps 以上）最佳，击球瞬间不糊；普通 30fps 视频可用，但击球帧可能模糊，报告需注明；
- **时长**：单个动作拍 3-5 秒即可，重复 3-5 次取最好的一次；长视频用 `--start/--duration` 截取动作片段再分析；
- **画面**：背景简洁（白墙最佳）、光线充足、衣服与背景有对比；
- **抽帧**：运行 `scripts/extract_frames.py`，普通视频每秒 2 帧、慢动作每秒 5 帧。

## 图片细节标注（视频/照片分析必附）

诊断结论必须落到图上，让「哪里错了」一眼可见：

1. **骨骼检测**：`pose_detect.py` 对主角区域跑 33 关键点检测（主角太远先用 `annotate_frames.py crop` 放大 3×），输出骨架叠加图 + 关节角度 JSON；
2. **标注图**：`annotate_frames.py mark` 生成——红圈=问题部位、绿圈+箭头=理想位置、文字=量化角度（如「躯干后仰 16.8°」）；
3. **挥拍轨迹图**：`annotate_frames.py ghost`（trail 模式 + `--box` 聚焦主角）；
4. **改进对比**：多次分析同一动作时，用 `compare` 模式输出左右并排的「改进前 vs 改进后」。

### 量化角度表（报告必附）

| 指标 | 定义 | 本次数值 | 解读 |
|------|------|---------|------|
| 躯干后仰角 | 肩中点-髋中点连线与竖直方向夹角 | | 后仰程度（跳杀理想 ≤10°） |
| 持拍臂肘角 | 肩-肘-腕 夹角 | | 180=完全伸直；击球瞬间应接近伸直 |
| 持拍腕相对肩 | 腕在肩的前/后、偏移像素 | | 判断击球点在头后还是前上方 |
| 膝角 | 髋-膝-踝 夹角 | | 蓄力深浅与起跳状态 |

> 标注位置来自检测关键点坐标，属数据驱动；检测不到时才退回目测示意，且须注明。

## 输出纪律

1. **不确诊**：基于截图、抽帧序列或口述的判断是推测，需说明素材局限（角度、帧率、清晰度），建议多角度素材交叉验证；视频分析报告须注明「基于 N 帧样本的动态推断」；
2. **一次只抓 1-2 个问题**：列七八个问题用户一个都改不了，等于没说；
3. **每个问题必须配能自己练的纠正练习**，不能只说「你这里错了」；
4. **结尾给下一步行动项**：今天/这周先改什么。
